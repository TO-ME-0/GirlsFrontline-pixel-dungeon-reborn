## 1. 目标与边界

本次工作的目标是为关卡加入“单向行走”能力：每个地格可以禁止向 8 个方向中的任意方向离开。

已明确的边界：

- 单向数据由 `Level` 持有，但**生成、分配、维护由后续工作另行安排**，本会话不在 `Level.setSize` 中分配，也不写入任何房间生成逻辑。
- `PathFinder` 只负责“给定 `int[] oneWay` 时能正确寻路”，不持有、不读取 `Level`，不做任何静态缓存。
- 渲染部分当前只完成数据计算和图层骨架；贴图尚未接入，因此运行时被短路，不会加载贴图。

## 2. 数据模型（必须遵守）

### 2.1 字段

`Level` 中新增：

```java
//单向行走禁止方向，按格记录，位序 NW,N,NE,W,E,SW,S,SE
public int[] oneWay;
```

位置：`core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/levels/Level.java:166`

### 2.2 位定义

`oneWay[pos]` 的每一位表示“从该格向该方向**离开**被禁止”：

| 方向 | 位值 |
|---|---|
| NW 左上 | `1 << 0` = 1 |
| N 正上 | `1 << 1` = 2 |
| NE 右上 | `1 << 2` = 4 |
| W 左 | `1 << 3` = 8 |
| E 右 | `1 << 4` = 16 |
| SW 左下 | `1 << 5` = 32 |
| S 下 | `1 << 6` = 64 |
| SE 右下 | `1 << 7` = 128 |

方向索引顺序与 `PathFinder.NEIGHBOURS8` 一致：`NW, N, NE, W, E, SW, S, SE`。

### 2.3 无效数据

以下情况一律视为“没有任何单向限制”：

- `oneWay == null`
- `oneWay.length != level.length()`
- 数组存在但全为 0

`PathFinder` 在公开重载入口统一归一化前两种；全 0 不需要特殊处理（判断永远为 false）。

### 2.4 单向边的定义

一条“真正单向”的边 `S → D` 必须同时满足：

1. `S` 允许向 `D` 走：`(oneWay[S] & bit(dir(S→D))) == 0`
2. `D` 禁止走回 `S`：`(oneWay[D] & bit(dir(D→S))) != 0`

只满足“允许”而没有反向禁止的，是普通双向通道，不应画箭头。

## 3. 已完成：PathFinder

文件：`SPD-classes/src/main/java/com/watabou/utils/PathFinder.java`

### 3.1 方向掩码常量

位置：约 `:51-66`

- `DIR_BITS`：对应 `dir` 数组顺序
- `DIRLR_BITS`：对应 `dirLR` 数组顺序（正向扩散用）
- `DIRLR_OPP_BITS`：对应 `-dirLR[i]`（反向扩散用）

注意：`dir` 和 `dirLR` 的元素顺序不同，必须使用不同的掩码表，不能共用下标。

### 3.4 方向检查插入点

| 位置 | 检查 |
|---|---|
| `find_` 选步循环 `:189` | `(oneWay[s] & DIR_BITS[i]) != 0` → 跳过 |
| `getStep_` 选步循环 `:230` | `(oneWay[from] & DIR_BITS[i]) != 0` → 跳过 |
| `getStepBack_` 选步循环 `:270` | `(oneWay[s] & DIR_BITS[i]) != 0` → 跳过 |
| `buildDistanceMap(from,to)` 反向 BFS `:403` | `(oneWay[n] & DIRLR_OPP_BITS[i]) != 0` → 跳过 |
| `buildDistanceMap(from,to[])` 反向 BFS `:455` | 同上 |
| `buildEscapeDistanceMap` 正向 BFS `:507` | `(oneWay[step] & DIRLR_BITS[i]) != 0` → 跳过 |

关键语义：

- 反向 BFS 从目标向外扩散，实际允许的移动是 `n → step`，所以查 `n` 格的**反方向** `DIRLR_OPP_BITS`。
- 正向逃跑扩散实际移动是 `step → n`，所以查 `step` 格的**正方向** `DIRLR_BITS`。
- `buildDistanceMap` 中 `n == from` 的原有特判仍保留，但方向检查要在它之前；顺序是“边界检查 → 方向检查 → `n == from || passable`”。
- 三个选步循环必须判方向，不能只靠距离场；`distance[n]` 更小不代表 `s → n` 合法。

### 3.5 未改动的部分

- `public buildDistanceMap(to, passable)` / `(to, passable, limit)` 保持对称语义，供炸弹、陷阱、范围判定使用。
- 旧调用方无需修改即可编译，行为不变。

## 5. 已完成：箭头渲染逻辑

文件：`core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/tiles/OneWayTilemap.java`

### 5.1 图层结构

- `extends Tilemap`，使用 8×8 的 `TextureFilm`（`DungeonTilemap.SIZE / 3`）。
- 数据长度 = `(level.width*3) * (level.height*3)`。
- 每个子格的值：`-1` 表示无箭头，`1..8` 表示箭头方向帧。
- 位置公式：`data[(y*3 + sub/3) * (width*3) + x*3 + sub%3]`。

### 5.2 子格映射

子格编号 1..9（左上到右下）。

| 单向方向 | 源格子格 | 目标格子格 | 帧 ID |
|---|---|---|---|
| NW | 1 | 9 | 8 |
| N | 2 | 8 | 1 |
| NE | 3 | 7 | 2 |
| W | 4 | 6 | 7 |
| E | 6 | 4 | 3 |
| SW | 7 | 3 | 6 |
| S | 8 | 2 | 5 |
| SE | 9 | 1 | 4 |

两端子格使用**同一个箭头方向**（即实际移动方向）。例如 B 在 A 右边、仅允许 B→A：B 的子格 4、A 的子格 6 都画向左箭头。

### 5.3 合并规则

对每个 2×2 区域（TL/TR/BL/BR）检测四边方向一致的完整单向流；命中后把四个中心角子格统一为该流向：

| 流向 | 判定条件 | 覆盖子格 |
|---|---|---|
| W | TR→TL、BR→BL、BR→TL、TR→BL | TL 9、TR 7、BL 3、BR 1 → W |
| E | TL→TR、BL→BR、TL→BR、BL→TR | 同上四个子格 → E |
| N | BL→TL、BR→TR、BR→TL、BL→TR | 同上四个子格 → N |
| S | TL→BL、TR→BR、TL→BR、TR→BL | 同上四个子格 → S |

说明：

- 用户只举例了 W，本实现对称扩展到 E/N/S 四个旋转方向。
- 四个中心角子格分别只属于当前 2×2 区域，不会被相邻 2×2 重复覆盖。
- 多流向条件互斥（互为反向），不会同时命中。

### 5.4 贴图契约（后续补图时需要）

- 文件名：`environment/one_way.png`
- 帧尺寸：8×8
- 帧 0：空白
- 帧 1..8：依次为 `N, NE, E, SE, S, SW, W, NW`
- 帧 `-1` 不渲染，不会去取贴图。

### 5.5 刷新与绘制顺序

- `refresh()` 重新计算整个箭头数组并 `updateMap()`。
- 箭头层加入 `terrain` 组的 `terrainFeatures` 之后，位于地形之上、角色/物品之下。
- 仅在两端都 `passable` 时渲染；墙、深坑等不显示箭头。

## 9. 已知坑与注意事项

1. **方向语义**：位记录在“离开的格子”上，即 `oneWay[from]`。不要写成“禁止进入”。
2. **反向 BFS 取反**：`n = step + dirLR[i]` 时，实际移动是 `n → step`，必须用 `DIRLR_OPP_BITS[i]`。
3. **`n == from` 特判**：方向检查要放在 `n == from || passable[n]` 之前，否则起点格可能绕过方向限制。
4. **选步循环也要判方向**：只改 BFS 不够。
5. **缓存路径**：Mob/Hero 会复用上一回合的 `path`，单向状态变化后必须重新校验。
6. **`Dungeon.findStep` 相邻快路径**：唯一完全绕过 PathFinder 的入口。
7. **PathFinder 不持有 Level**：`SPD-classes` 不依赖 core；`oneWay` 只作为参数传入，避免查种 worker 线程串数据。
8. **渲染的端点方向**：箭头方向 = 实际移动方向，源格和目标格两端相同；不是“互相指向”。
9. **渲染只画真正单向边**：必须反向被禁止，否则双向通道也会出箭头。
10. **合并规则互斥**：同一 2×2 不可能同时满足 W/E 或 N/S，因为需要互为反向的单向边。
11. **贴图帧序**：`-1` 为不渲染；`1..8` 的顺序必须与 `DIR_FRAME` 一致，否则方向会错乱。
12. **性能**：当前 `updateMap(cell)` 会触发箭头层全量重算；贴图接入后如果频繁开门/改地形，可改为局部更新。
13. **未分配数组**：`Level.oneWay` 默认 null，任何生成/写入方必须先分配 `new int[level.length()]`。
