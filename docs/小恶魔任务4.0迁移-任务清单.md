## 二、接入实施决策记录（重要）

> 本节记录接入过程中与 4.0 原版的所有偏离点，验收与后续补图以本节为准。

### 2.1 架构决策
- **支线层不移植 LevelTransition**：改用 `levels/triggers/VaultEntranceTrigger.java`（默认 touch 路径激活），`enterVault()` 完整还原 4.0 入口流程（门禁沉默拦截 → WndOptions 确认 → hero.live()+满血 → EscapeCrystal 取得/新建 → storeHeroBelongings → 水晶 collect → 穿 ClothArmor 并 identify → updateHT(false) → 切换）。`InterlevelScene` 新增 ACCESS（accessLevelId/accessPos）与 RETURN（returnLevel/returnPos）模式；`returnPos=-4` 特例=扫描 triggers 找 VaultEntranceTrigger 格。
- **Quest 保持实例风格**：配合 reborn 多上下文架构（`Dungeons.cur()` 按线程路由主游戏/查种 worker），未改 4.0 的静态结构。
- **三基类内联**：reborn 无 Shaman/Golem/Ghoul 基类 → VaultShaman 改 extends Mob implements Callback（内联 4.0 Shaman 逻辑，DM100 式 zap：doAttack 先结算伤害再 sprite.zap 纯视觉，call()→next()）；VaultGolem/VaultGhoul 同理内联。
- **GridBuilder 原样移植**：LoopBuilder 近似方案实测失败——金库 18 个固定 11×11 房间超出随机摆放容量，`placeRoom` 死循环触发 levelgen 10 秒超时崩溃。已将 4.0 `GridBuilder` 完整搬入 `levels/builders/`（网格对齐紧凑布局，地图尺寸由 RegularPainter 按房间包围盒 `setSize`，两版血统一致无需适配），`VaultLevel.builder()` 改回 `new GridBuilder()`。
- **level.entrance 落点坑**：4.0 金库入口房不设 `level.entrance`（原版走 transition 落点），reborn 触发器方案依赖 `switchLevel` 的 `-1 → level.entrance` 解析，漏设会导致落点=0（左上角墙格）→ FOV 扫描越界崩溃。已在 VaultEntranceRoom 补 `level.entrance = entrance`（对齐 MineEntrance 写法）。
- **zap 委托方向相反（StackOverflow 级）**：4.0 的 `CharSprite.zap(int)` 委托给 `zap(int,Callback)`（两参是基础实现）；reborn 恰好相反（两参虚派发到单参）。凡重写 `zap(int)` 的精灵内部**禁止**调 `zap(cell, null)`，否则无限递归爆栈（且 StackOverflow 写不出崩溃报告）。VaultBossElementalSprite 两处已改 `super.zap(cell)`。
- **Mob API 差异**：无 INVESTIGATING 状态（→HUNTING）；无 `activateSteathGameplayBehaviour/handleRecentAttackers` 等（删除）；Invisibility 驱散用 `Buff.detach(this, Invisibility.class)`；`Random.shuffle` 不支持 int[]（手写 Fisher-Yates）。
- **其他**：无 `PixelScene.shake`（→`Camera.main.shake`）；无 `GameScene.targetedCell`（→`effects.TargetedCell`，构造仅 `(pos,color)`，用法 `sprite.parent.add(new TargetedCell(p, 0xFF0000))`）；无 `Badges.validateDeathFromEnemyMagic`（整行删）；无 AscensionChallenge（入口门禁删此分支）；`Item.level(int)` 返回 void；`Bundle.getIntArray` 缺键返回 null。
